## Эталон и данные

Исходный SHA-256 `LAYOUT_FOLLOWUP_CANDIDATE.html` — `62666e36b71b71d7c0de474f36a645178e4b137bdbb2822f2bc815805f17d705`. Для перевода и карты также открыты профильные HTML. С тестовой страницы передаётся только вымышленный набор значений для сравнения, разметка эталона и обработчики остаются из архива. Декоративная обёртка убрана при измерении поверхности. Lucide загружается локально и виден в снимках. Основные числа, дата, остатки счетов и доли согласованы там, где модели совместимы.

Категории в эталоне ведут старый учёт распределённых поступлений. В патче фактическая доступность берётся из действующей модели, а план расхода берётся из расписаний и долей. Прототип долей использует текущую общую плановую сумму даже при просмотре соседнего месяца. Патч хранит исторические месяцы. На планы доходов приложение добавляет связанные ожидания. В платежах состав групп определяется сохранёнными расписаниями, паузами и активными фактами. [Принятые решения и предыдущая приёмка](../ACCEPTANCE.md)

## Переход с опубликованной версии

Worker `0097d58` загружал HTML с сети и не знал о плашке. Когда новые файлы доступны, первое сетевое открытие или перезагрузка получает новый HTML с версионными именами JS и CSS. Если новая оболочка уже открыта, она подтверждает worker с тем же кодом без показа предложения. Дальнейшие обновления открытой версии проходят вручную. Если все вкладки закрыты, браузер может завершить активацию ожидающего worker при следующем открытии.

Новый worker проверяет по SHA-256 весь набор файлов до появления плашки. Управляемые загрузки HTML и ресурсов используют кэш соответствующей активации. Общая IndexedDB сохраняется. При устаревшей записи из второй вкладки сохранение отклоняется, форма остаётся доступной.

Новая версия сохраняет ранее открытые базы и их исходные примеры. Новый профиль браузера либо другое устройство дают чистый экземпляр. Для очистки на текущем устройстве пользователь может удалить данные сайта в настройках браузера. Это удалит локальные записи и может затронуть другие приложения с тем же доменом. Очистка кэша worker сама по себе сохраняет данные IndexedDB.

cd source

npm run build
npm run test:financial
npm test
FINRATE_SCREENSHOTS=/tmp/finrate-regression npm run test:acceptance
npm run test:update
FINRATE_REFERENCES=/путь/к/UI_Lab npm run test:visual

Пять денежных проверок, четыре комбинации размера и темы в основном прогоне, сквозные связанные цепочки на 320 и 390 px, отдельные обновление и первый запуск. Для браузерных тестов нужен локальный HTTP-сервер, который поднимается сам. Тестовые записи создаются только через изолированный тестовый сервер, запуск приложения на GitHub Pages их не добавляет.
