# Приёмка исправлений по UX-аудиту FinRate Full

Проверенная версия — `0.2.0-test.3` · `c754e34f087db10f`. База до исправлений — `0.2.0-test.2` на [8fd14ef](https://github.com/kqh2rnnnmm-dot/finrate-full-test/commit/8fd14ef2dd5951069b03022751cf076738da8819).

Сравнение проведено в Chromium на 320 × 568 и 390 × 844 в обеих темах. В браузерах использованы изолированные профили, одни и те же вымышленные данные и фиксированная дата. Для визуального разбора Product Design проверены отрисованные состояния и последовательность действий. Для Frontend Testing & Debugging использован Playwright, поскольку Browser plugin отсутствовал. Физический iPhone и VoiceOver не проверялись.

[Пары экранов, состояния и проверка обновления](ux-audit/README.md)

## Повторение

```sh
cd source
npm install --no-package-lock
npm run build
npm run test:financial
npm test
FINRATE_SCREENSHOTS=/tmp/finrate-regression npm run test:acceptance
FINRATE_UPDATE_SCREENSHOTS=/tmp/finrate-update npm run test:update
FINRATE_REFERENCES=/путь/к/UI_Lab FINRATE_VISUAL_SCREENSHOTS=/tmp/finrate-reference npm run test:visual
npm run test:ux
```

Chromium подтвердил загрузку приложения, наличие рабочего экрана, отсутствие ошибок консоли в UX-прогоне, зоны нажатия выбранных контролов, фокус и реальные переходы. Прогон с эталоном использовал Lucide из штатной зависимости. Денежное ядро и worker сохранены. Тест обновления проверяет чистый профиль, неполную загрузку, черновик, офлайн, вторую вкладку и переход с опубликованной версии `0.2.0-test.2` с собственной записью.

## Чек-лист владельца

1. На iPhone открыть сводку, пролистать месяц и список, проверить суммы и видимость последней категории над переключателем.
2. Пройти из меню в планы и распределение, проверить «Шаг ползунка» и возврат из редактора доли. С VoiceOver проверить названия полей, фильтра, переключателя накоплений и статус отмены.
3. Записать часть ожидаемого дохода и проверить отображение оставшейся суммы. Открыть кредитку с долгом и без него и проверить ближайший срок.
4. Начать черновик и проверить ручное обновление при следующем выпуске. Сначала вернуться к черновику, затем подтвердить и убедиться, что сохранённые записи на месте.
